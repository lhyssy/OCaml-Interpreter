## 项目代码运行方法

本项目为dune项目，可以提供的项目参数如下：

- `-i <filename> `：将`filename`作为输入流
- `-o <filename> `：将`filename`作为输出流
- `-ast `：将解析得到的AST输出到终端
- `-ir `：将解析得到的IR输出到终端
- `-opt`：启用优化程序（被忽略）

示例：

如下代码为默认的结构，从标准输入流读取，并输出到标准输出流

```bash
dune exec interpreter_project
```

如下代码从文件中读取并且读出到文件，且输出IR结构

```bash
dune exec interpreter_project -- -i test/06_continue.tc -o test_results/res.s -ir
```

如下代码从文件中读取并且读出到文件，且输出AST结构

```bash
dune exec interpreter_project -- -i test/06_continue.tc -o test_results/res.s -ast
```

## 项目代码测试方法

你可以使用如下指令对于`test/`文件夹中存放的所有文件（不包含旧文件）进行批量测试：

```bash
dune runtest
```

如果能够生成所有代码，将会声明如下提示：

```
所有测试文件已编译完成，结果存储在 test_results 目录中
请自行使用venus插件测试实际的代码运行结果.
```

## 在 QEMU 上运行生成的 RISC-V 二进制

本项目默认生成适用于 RISC-V 裸机环境的汇编（无 C 运行时/启动例程）。如果使用 `riscv32-unknown-elf-gcc` 链接，得到的是裸机 ELF，该产物不能直接由 `qemu-riscv32`（Linux 用户态仿真器）运行，会出现 “Invalid ELF image for this architecture” 或缺少 `_start` 的告警。

有两种建议的运行方式：

1) 使用模拟器加载裸机汇编（如 Venus/Spike/OVPSIM）
   - 推荐：使用配套的 Venus 插件按提示运行。

2) 若需用 QEMU 运行，需使用 Linux 交叉编译工具链并提供最小入口
   - 安装交叉编译器（Ubuntu 示例）：
     ```bash
     sudo apt-get update
     sudo apt-get install qemu-user gcc-riscv64-linux-gnu gcc-riscv32-unknown-elf
     # 如果没有 riscv32-linux-gnu-gcc，可自行构建或改用 64 位 Linux 目标（qemu-riscv64）
     ```
   - 为生成的 `program.s` 提供一个 `_start` 入口或链接到 C 运行时。简便做法是写一个极简 `crt0`，将 `main` 的返回值传给 `ecall` 退出；或改为 Linux 目标并链接标准启动文件：
     ```bash
     riscv32-linux-gnu-gcc -static -O2 -o program program.s
     qemu-riscv32 ./program
     echo $?
     ```
   - 注意：若仍使用 `riscv32-unknown-elf-gcc`，需自备链接脚本与启动文件定义 `_start`，并通过 ecall 退出。
